# EL05 电机 MIT 运控模式 CAN 协议速查

> 来源: `EL05使用说明书260713.pdf` 第 4 章「驱动器协议及使用说明」
> 用途: 编写 `edulite05_motor` 驱动的协议参考,按帧格式逐字段核对用

## 1. 总线基本信息

| 项目 | 值 |
|---|---|
| 通信接口 | CAN 2.0 |
| 波特率 | **1 Mbps** |
| 帧格式 | **29 位扩展帧**(注意: 不是标准帧!) |
| 数据区 | 8 字节 |
| 上电默认模式 | 运控模式(MIT) |
| 手册示例主机 CAN_ID | `0xFD`(bit15~8) |
| 手册示例电机 CAN_ID | `0x7F`(实际以电机配置为准,可用通信类型 7 修改) |

## 2. 扩展帧 ID 结构(所有帧通用)

```
29 位 ID = [ bit28~24 通信类型 ] [ bit23~8 数据区2 ] [ bit7~0 目标地址 ]
```

| 字段 | 位 | 说明 |
|---|---|---|
| 通信类型 | bit28~24 | 帧类型编号(1/2/3/4/6…) |
| 数据区2 | bit23~8 | **随帧类型变化**:运控指令放力矩,命令帧放主机 ID,反馈帧放电机 ID+故障+状态 |
| 目标地址 | bit7~0 | 主机→电机帧: 目标电机 CAN_ID;电机→主机帧: 主机 CAN_ID |

## 3. 帧格式详解

### 3.1 通信类型 1:运控模式电机控制指令(主机 → 电机,1kHz 周期发)

**ID**: `type=0x1`, **bit23~8 = 前馈力矩 t_ff**(16bit 编码,±6Nm), bit7~0 = 目标电机 CAN_ID

**数据区 8 字节(全部大端,高字节在前)**:

| 字节 | 内容 | 编码 | 量程 |
|---|---|---|---|
| Byte0~1 | 目标角度 p | 16bit 无符号 | -12.57 ~ 12.57 rad |
| Byte2~3 | 目标角速度 v | 16bit 无符号 | -50 ~ 50 rad/s |
| Byte4~5 | Kp(刚度) | 16bit 无符号 | 0 ~ 500 |
| Byte6~7 | Kd(阻尼) | 16bit 无符号 | 0 ~ 5 |

> ⚠️ **力矩不在数据区,在扩展帧 ID 的 bit23~8**——这是本协议最容易写错的地方。

### 3.2 通信类型 2:电机反馈数据(电机 → 主机)

**ID**: `type=0x2`, bit23~8 = `[bit22~23 模式状态][bit16~21 故障位][bit8~15 电机 CAN_ID]`, bit7~0 = 主机 CAN_ID

**数据区 8 字节(全部大端)**:

| 字节 | 内容 | 编码 | 量程 |
|---|---|---|---|
| Byte0~1 | 当前角度 | 16bit 无符号 | -12.57 ~ 12.57 rad |
| Byte2~3 | 当前角速度 | 16bit 无符号 | -50 ~ 50 rad/s |
| Byte4~5 | 当前力矩 | 16bit 无符号 | -6 ~ 6 Nm |
| Byte6~7 | 当前温度 | 16bit 无符号 | ℃ × 10(**解析后要 ÷10**) |

**ID 内嵌的故障位(bit16~21,1 = 有故障)**:

| 位 | 含义 |
|---|---|
| bit21 | 未标定 |
| bit20 | 堵转过载故障 |
| bit19 | 磁编码故障 |
| bit18 | 过温 |
| bit17 | 三相电流故障 |
| bit16 | 欠压故障 |

**ID 内嵌的模式状态(bit22~23)**:

| 值 | 模式 |
|---|---|
| 0 | Reset 模式(复位) |
| 1 | Cali 模式(标定) |
| 2 | Motor 模式(运行) |

### 3.3 通信类型 3:电机使能运行(主机 → 电机)

- ID: `type=0x3`, bit23~8 = 主机 CAN_ID(bit15~8), bit7~0 = 目标电机 CAN_ID
- 数据区: **8 字节全 0**
- 应答: 电机反馈帧(类型 2)
- **上电后必须先发此帧,电机才响应运控指令**

### 3.4 通信类型 4:电机停止运行(主机 → 电机)

- ID: `type=0x4`, bit23~8 = 主机 CAN_ID, bit7~0 = 目标电机 CAN_ID
- 数据区: 正常停止**全 0**; **Byte[0]=1 时 = 清故障**
- 应答: 电机反馈帧(类型 2)

### 3.5 通信类型 6:设置电机机械零位(主机 → 电机)

- ID: `type=0x6`, bit23~8 = 主机 CAN_ID, bit7~0 = 目标电机 CAN_ID
- 数据区: **Byte[0]=1**,其余 0
- 注意: CSP 和运控模式下标零有效,PP 模式标零会被屏蔽

### 3.6 通信类型 0:获取设备 ID(调试用)

- ID: `type=0x0`, bit23~8 = 主机 CAN_ID, bit7~0 = 目标电机 CAN_ID,数据区全 0
- 应答: ID `type=0x0`, 数据区 = 64 位 MCU 唯一标识符
- 用途: **验证总线和扩展帧收发链路是否打通**

## 4. 量程与换算

| 物理量 | 最小值 | 最大值 | 编码位数 |
|---|---|---|---|
| 位置 p | -12.57 rad | 12.57 rad | 16bit |
| 速度 v | -50 rad/s | 50 rad/s | 16bit |
| 力矩 t_ff | -6 Nm | 6 Nm | 16bit |
| Kp | 0 | 500 | 16bit |
| Kd | 0 | 5 | 16bit |

编码公式(手册 4.4 程序样例):

```c
uint16_t float_to_uint(float x, float x_min, float x_max, int bits)
{
    float span = x_max - x_min;
    float offset = x_min;
    if (x > x_max) x = x_max; else if (x < x_min) x = x_min;   // 手册样例带限幅
    return (uint16_t)((x - offset) * ((float)((1 << bits) - 1)) / span);
}
```

## 5. 运控模式控制公式

```
t_ref = Kd × (v_set − v_actual) + Kp × (p_set − p_actual) + t_ff
```

电机**内部自带 PD 闭环**,按公式折算期望 Iq 电流并输出。三种用法(手册 4.3.1 演示):

| 参数组合 | 效果 |
|---|---|
| v_set=1, Kd=1, 其余 0 | 电机以 1 rad/s 匀速运行 |
| 全 0,Kd=1 | **阻尼模式**:外部转动电机有阻尼(注意会发电,需电源馈电防过压) |
| p_set=5, Kp=1, Kd=1, 其余 0 | 电机运行到位置 5 并保持(Kp 越大保持力越大,Kd 是阻尼防摇摆) |
| 只有 t_ff | **纯力控**:电机输出指定力矩(板端闭环用) |

## 6. 标准使用流程

```
① 上电(默认运控模式)
② 发送使能帧(类型 3)
③ 周期发送运控指令(类型 1)── 1kHz 推荐
④ 接收反馈帧(类型 2)── 解析角度/速度/力矩/温度/故障/状态
⑤ 停止: 发送停止帧(类型 4);失联保护也应发类型 4
```

## 7. 角度范围与多圈计数(手册 4.2 节)

- 上电默认位置范围 **0 ~ 2π**(`zero_sta` 标志位默认 0)
- 修改 `zero_sta` = 1(类型 18 写 + 类型 22 保存)后,上电默认位置为 **-π ~ π**
- 新版固件反馈角度为**周期性循环 -4π ~ 4π**,可用于记圈数(注意 ±2π 跳变检测)
- 编码器标定: `iq_test` 置 1 后重启,初始化标定更精确;齿槽标定需上位机配合

## 8. 其他相关帧(简要)

| 类型 | 用途 |
|---|---|
| 7 | 设置电机 CAN_ID(立即生效) |
| 17 | 单个参数读取(参数表 index 寻址) |
| 18 | 单个参数写入(掉电丢失,配合 22 保存;切换 runmode/写 limit_cur 等) |
| 21 | 故障反馈帧(电机主动上报详细 fault 值,Byte0~3) |
| 22 | 电机数据保存帧(配合 18 做掉电保存) |
| 23 | 波特率修改帧 |
| 24 | 电机主动上报帧 |
| 25 | 协议切换帧(MIT ↔ CANopen,重新上电生效) |

> 类型 21 的 fault 值(Byte0~3)与类型 2 反馈 ID 里的 6 位故障字段**不是同一组**,前者更详细: bit16=A 相过流、bit14=堵转、bit9=位置初始化、bit8=硬件识别、bit7=编码器未标定、bit5/4=C/B 相过流、bit3=过压 60V、bit2=欠压 12V、bit1=驱动芯片、bit0=过温 135℃。

## 9. 驱动实现要点(本工程内)

1. **扩展帧**: 发送前必须设 `txconf.IdType = FDCAN_EXTENDED_ID`(bsp 的 CANRegister 默认写死标准帧)
2. **每帧现拼 ID**: 运控指令的 ID 含实时变化的 t_ff,不能只在 Init 配一次
3. **接收过滤器**: bsp_fdcan 已改造支持扩展帧掩码过滤(`FDCAN_EXTENDED_ID + FDCAN_FILTER_MASK`)。每电机过滤键 = `(2<<24) | (电机ID<<8) | 0xFD`,掩码 = `0x1F00FFFF`(比对类型+电机ID+主机ID,忽略每帧变化的故障/状态位)。注意 CubeMX 的 FDCAN `ExtFiltersNbr` 必须 > 0(本工程 FDCAN1 已设为 8,重新生成代码后要重设)
4. **温度 ÷10**、**大端序**、**力矩进 ID** 是三个最常写错点
